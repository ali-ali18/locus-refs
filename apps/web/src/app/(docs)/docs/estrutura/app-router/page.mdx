## Route groups

Os parênteses na pasta criam um grupo sem impactar a URL. `/login` é acessível em `/login`, não em `/(auth)/login`.

Isso serve para compartilhar layouts entre rotas sem criar segmentos de URL extras. Por exemplo, todas as rotas dentro de `[workspaceSlug]/` compartilham o mesmo layout com sidebar e header.

## [workspaceSlug]

Segmento dinâmico — o slug do workspace ativo aparece na URL (`/meu-workspace/notes`). O layout desse grupo valida a sessão e carrega o contexto do workspace. Rotas fora desse grupo (como `/login`) são públicas.

## api/

Serverless API routes. Cada `route.ts` exporta handlers HTTP (`GET`, `POST`, `PATCH`, `DELETE`). Todas as rotas de negócio usam `requireWorkspaceAccess()` do `src/server/` para validar a sessão antes de processar a requisição.
